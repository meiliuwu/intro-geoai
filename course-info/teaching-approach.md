# Teaching approach

Every lecture is interactive. Students arrive having read and annotated the week's papers, so lecture time goes on discussion rather than first exposure. In a typical 2-hour lecture, about 40 minutes is short input and more than an hour is student activity.

## A typical 2-hour lecture

| Minutes | Segment | What happens |
| --- | --- | --- |
| 0–10 | Hook and poll | A provocative image, map or claim, with a live poll. Results from last week's lab reflection are shown here. |
| 10–30 | Concept burst 1 | A short, figure-led mini-lecture with one peer-instruction question (vote, discuss with a neighbour, vote again). |
| 30–50 | Paper clinic | A student-led jigsaw on the pre-readings: expert groups on one paper each, then mixed groups teach each other. From Week 2 a rota group leads it. |
| 50–60 | Break | |
| 60–75 | Concept burst 2 | Mini-lecture plus a short live preview of the lab. |
| 75–110 | Main group activity | The week's signature activity (design canvas, error gallery, map critique, role-play), with one-minute report-backs. |
| 110–120 | Wrap | An "ethics minute" on the week's case, then an exit ticket. |

## Formats used across the course

| Format | How it runs | Weeks |
| --- | --- | --- |
| Social annotation of readings | Students annotate the papers online before class; the most-asked questions open the lecture. | All |
| Peer instruction | A concept question, individual vote, two minutes of discussion, then a re-vote. | 1–3 |
| Jigsaw reading | Each group masters one paper, then regroups so every table has an expert on each. | All |
| GeoAI design canvas | Groups fill Data → Structure → Model → Validation → Risk for a scenario and pitch it in one minute. | 1, 3, 5 |
| Error gallery | Printed misclassified tiles or maps on the walls; groups diagnose why the model failed. | 2, 5 |
| Real or fake? | A quiz on AI-generated versus real maps and satellite images. | 6 |
| Map critique | A studio-style critique of an AI-made map against cartographic principles. | 6 |
| Stakeholder role-play | Groups argue a deployment decision as council, residents, technology vendor and regulator. | 7 |
| Gallery walk | Group posters on the walls; students rotate and leave written feedback. | 4, 5 |
| GeoAI in the news | A student pair presents one recent news item in five minutes. | 2–7 |
| Exit ticket | One thing learned, one thing still unclear. | All |

## Threads that run through every week

- **Spatial validation.** Random versus spatial cross-validation appears in Weeks 1, 2, 3 and 5, so students learn to distrust optimistic accuracy.
- **Reproducible practice.** Every lab fixes random seeds, records library versions and is saved to the student's own GitHub repository.
- **Glasgow and Scotland as a running case.** Weeks 3, 4, 5 and 7 use Scottish data where it exists.
- **Lab to lecture.** Each lab ends with a reflection question that opens the next lecture.

## In the labs

- **Pair programming:** a driver types and a navigator reads ahead; they swap at each part of the notebook.
- **Core and stretch:** every notebook has core steps for everyone and optional stretch tasks for those with more machine-learning experience.
- **Showcase:** students post one map or figure from each lab to a shared board; a few open the next lecture.
