# Assessment

| Component | Weight | When | Linked to |
| --- | --- | --- | --- |
| Essay (up to 2,000 words) | 40% | After Week 7 | A theme from the lectures |
| Oral presentation of the project proposal | 10% | Week 8 | The GeoAI design canvas |
| Project report (up to 2,000 words) | 50% | After Week 10 | The lab techniques, applied to a problem of your choice |

Detailed briefs, deadlines and marking criteria are published on the course's learning platform. This page explains how the weekly work feeds each component.

## Essay themes

Each lecture ends with a debate that can grow into an essay. Example themes:

| Week | Theme |
| --- | --- |
| 1 | Is GeoAI just AI applied to maps? Argue a position using the tests of spatial explicitness. |
| 2 | Satellite imagery is a distinct modality: what follows for model design and evaluation? |
| 3 | Can data-driven models be trusted where we have no observations? |
| 4 | What do big geodata reveal about places, and whom do they leave out? |
| 5 | Street-level AI and the risk of stigmatising neighbourhoods. |
| 6 | Who is the author of an AI-generated map? |
| 7 | Is location privacy compatible with useful mobility analytics? |

## Project: Weeks 8–10

| Week | Session (4 hours) | What you do |
| --- | --- | --- |
| 8 | Proposal presentations and peer feedback | Pitch your project using the [GeoAI design canvas](../resources/teaching-materials/geoai-design-canvas-A3.pdf). Peers give one strength, one risk and one question. |
| 9 | Project lab I | Build the data pipeline and a baseline in your GitHub repository; agree your spatial validation design with a tutor. |
| 10 | Project lab II | Compare models, map errors, write a model card and a README that lets someone else rerun your work. |

### Your project repository should contain

- A `README.md` explaining the question, the data (with sources and licences) and how to run the code.
- Notebooks or scripts that run from top to bottom without manual steps.
- Fixed random seeds and a record of library versions.
- Results reported with the kind of split they came from (random or spatial).
- A short model card covering intended use, data, performance across places and known limitations.
